## What Went Well

### 1. Backward Compatibility Strategy ⭐
**Story 1.2 established the re-export pattern**
- Used re-exports in Python (`app/models.py` → `features/auth/models.py`)
- Used re-exports in TypeScript (`hooks/useAuth.ts` → `features/auth/hooks/useAuth.ts`)
- **Impact:** All 55 template tests continued to pass without modification
- **Charlie (Senior Dev):** "That's senior-level thinking. We refactored without breaking anything."

### 2. Security-First Mindset Through Code Review
**Security gaps discovered and fixed in 3/6 stories**
- Story 1.4: Added rate limiting (3 requests/hour), token hashing (SHA256)
- Story 1.5: Fixed email enumeration prevention
- Story 1.6: Added CSRF protection via OAuth state parameter
- **Impact:** Production-ready auth system from day one
- **Alice (Product Owner):** "We didn't just implement features - we implemented them correctly."

### 3. Documentation Discipline
**Code review feedback immediately acted upon**
- Story 1.6: Added missing `.env.example` and OAuth setup docs after review
- Pattern: Team responds constructively to feedback
- **Impact:** Reduced onboarding friction for future OAuth setup

### 4. Strong Backend Test Coverage
**64 tests passing with comprehensive auth flow coverage**
- Magic link generation, verification, expiration
- Rate limiting, token hashing
- OAuth state validation, account linking
- **Dana (QA Engineer):** "Backend coverage is great. 64 tests is solid."

## Challenges & Struggles

### 1. Docker Volume Sync Issues (Recurring)
**Affected Stories:** 1.4, 1.5
- Migration files created inside Docker containers weren't syncing to local filesystem
- Team had to use `docker compose cp` to copy files manually
- **Time Impact:** ~30-60 minutes per occurrence
- **Root Cause:** Docker volume configuration issue
- **Status:** Workaround documented, needs permanent fix

### 2. Alembic Autogenerate Limitations
**Affected Story:** 1.3
- Autogenerate couldn't detect SQLAlchemy-specific features (`sa_column_kwargs`)
- Team had to manually write migrations for timestamp auto-update
- **Impact:** Manual migration writing required for advanced features
- **Mitigation:** Document pattern for future reference

### 3. Frontend Testing Gap (Technical Debt)
**Affected: All Stories**
- No frontend test framework exists (Vitest/React Testing Library not set up)
- All frontend tests marked "deferred - no test framework set up"
- **Risk:** Untested UI code, form validation, navigation flows
- **Severity:** MEDIUM-HIGH
- **Recommendation:** Set up test framework before Epic 2 UI stories

### 4. Token Expiration Inconsistency
**Affected Stories:** 1.4, 1.5, 1.6
- Registration magic link creates 8-day JWT (`ACCESS_TOKEN_EXPIRE_MINUTES`)
- Login creates 30-day JWT (`LOGIN_TOKEN_EXPIRE_DAYS`)
- OAuth creates 30-day JWT
- **Impact:** Confusion, security policy unclear
- **Severity:** LOW
- **Status:** Needs decision and documentation

### 5. TanStack Router Route Generation Confusion
**Affected Story:** 1.4
- New route files weren't recognized until vite dev server started
- Router plugin regeneration triggered manually
- **Impact:** Development confusion, wasted time
- **Status:** Documented for future reference

## Lessons Learned

### Process Insights
1. **Code Review is Non-Negotiable** - Security issues caught in 50% of stories during review. Process is working.
2. **Security Needs Upfront Thinking** - Can we add security as a first-class AC consideration?
3. **Documentation Matters** - OAuth setup docs, .env.example prevent onboarding friction
4. **Tests Before Marking Done** - "Tests deferred" without strong rationale is accumulating debt

### Technical Insights
1. **Re-Export Pattern is Powerful** - Enabled complex refactoring without breaking existing code
2. **Tooling Has Limitations** - Alembic autogenerate, Docker volumes have gaps we need to work around
3. **JWT Expiration Should Be Consistent** - Need unified token policy (30-day vs 8-day)
4. **Frontend Testing Can't Wait** - Need test framework before building more UI

### Breakthrough Moments
**Story 1.2's re-export pattern** became the standard for all subsequent stories. This architectural pattern allowed seamless migration to feature-based structure.
